# Next improvements, ranked by observed failures

The broader workload suite challenges the earlier narrow fast-path wins. Kestrel is not yet an overall replacement that consistently outperforms direct Codex. Optimize task success first, then generation calls, then latency at equivalent success.

| Priority | Capability | Evidence and proposed acceptance condition |
| --- | --- | --- |
| 1 | Reliable recovery with typed failure branches | The initial recovery task stopped after diagnosis. Original-request completion checks are now added. Success/failure/completion dependencies are now implemented and covered by controller tests, but live recovery still shows unnecessary retries/replans. Compact argument repair now reduces discovery steps and passes three paired recovery cases, but still loses every recovery timing to direct Codex (COMPACT-RECOVERY.md). Next: repair only affected actions and verify on missing inputs, nonzero exits, stale hashes, and interrupted writes without duplicate side effects. |
| 2 | More deterministic data tools | CSV aggregation needed generated Python and three generation calls. A generic CSV/JSON query tool now removes that code-generation round trip. The Jev table recipe now avoids generation entirely for bounded grouped queries; three repeated sum/mean/count trials per arm matched correctness with lower median latency. See JEV-TABLES.md. Numeric JSON now binds directly into writes in the latest live trial, and short grounded edits can be embedded in the initial plan. Next: joins, sorting, projection, and schema inspection with independent Decimal-based oracles and unseen schemas, not benchmark-specific answers. |
| 3 | Lower-overhead execution loop | Initial evidence now removes inspection-only planning for small explicitly named files; multi-file work uses one generation call in the latest trials but does not consistently beat the direct baseline. Prototype provider-native tool calling and compare it with the full-plan DAG; keep Jev for bounded choices and checks. Verified tool-answer reuse now avoids final generation when Jev approves it; this alone did not consistently reduce latency. Batch independent Jev decisions and avoid re-sending full catalogs and duplicate evidence. Require equal or better correctness before adopting a latency win. |
| 4 | Tested, parameterized workflow reuse | Existing workflow memory supplies hints, not proven replay speedups. Add versioned executable recipes with input/content hashes, permission preconditions, invalidation, and explicit activation. Benchmark unseen parameters and changed files before claiming saved planning calls. |
| 5 | Better evidence retrieval and user control | Current prompts use excerpts from the latest observations. Add provenance-aware retrieval for long tasks, visible remaining requirements, and steering/approval behavior that survives interruption. Test long documents and multi-turn corrections. |
| 6 | Reproducible quality/performance gates | Preserve task fixtures, traces, source hashes, correctness graders, failed runs, token/cache counts, and latency. Use repeated randomized-order trials and a frozen held-out suite before quoting medians/p95 or general superiority. Actual provider billing data is needed for dollar-cost claims. |

Do not add autonomous external actions, more providers, or larger models merely to expand the feature list. The strongest immediate gains come from reliable completion, reusable deterministic operations, and fewer unnecessary generation round trips. Jev checks reduce some risks but are not a mathematical correctness guarantee.
